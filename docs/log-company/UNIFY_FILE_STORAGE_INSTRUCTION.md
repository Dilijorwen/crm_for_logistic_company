# Как сделать MinIO единым хранилищем для модулей CRM

Статус — инструкция для реализации. Текущая конфигурация описана в [FILE_STORAGE.md](FILE_STORAGE.md).

## Что уже есть

Плагин `@log-company/plugin-file-storage` уже даёт модулям общий закрытый бакет `log-company-files` и реализацию `MinioStorageArea`. Документы рейсов, поставок и пользовательских папок обслуживает `plugin-process-documents`. Вложения карточек компаний и разрешительных документов обслуживает штатный NocoBase File Manager через тип хранилища `log-company-private-minio`. У чатов свой поток загрузки и доступа с тем же адаптером MinIO.

Объекты уже находятся в одном хранилище. Различается то, что происходит вокруг них. Например, документы поставок проверяют формат в своём HTTP-обработчике, а штатные вложения открываются через короткоживущую ссылку `fileStorage:open`. Задача — собрать повторяющиеся операции и правила в одном плагине.

## Границы компонентов

| Компонент | За что отвечает |
| --- | --- |
| `plugin-file-storage` | Настройки MinIO, области хранения, генерация ключей, проверка файлов, загрузка и чтение потоком, общие заголовки скачивания, обработка ошибок и очистка объектов. |
| Плагины документов и штатный File Manager | Связь файла с карточкой, папкой или сообщением, проверка прав на исходную запись и запись метаданных. |
| Файловый менеджер Log Company | Дерево `Компания/ВЭД/Рейс/Поставка`, учредительные и разрешительные документы, пользовательские папки. |
| PostgreSQL и MinIO | PostgreSQL хранит имя, связи, права и ключ объекта. MinIO хранит содержимое файла. |

Физический ключ объекта стабилен и генерируется сервером. Отображаемый путь строится из записей PostgreSQL. Например, при смене номера рейса меняется подпись папки, а существующий ключ MinIO остаётся прежним. Одна поставка в двух рейсах открывает один набор файлов.

## Порядок реализации

1. **Оставить один серверный вход для хранения.** В существующем `plugin-file-storage` создать сервис, который при загрузке приложения получает общую конфигурацию `FILE_STORAGE_*` и предоставляет контракты сохранения, чтения и удаления объектов. Переиспользовать клиент MinIO внутри приложения. Адаптеры документов, штатных вложений и чатов получают доступ к своим фиксированным областям `process-documents`, `attachments` и `chat-attachments`. Подключить их через существующие серверные порты и `peerDependencies`. У браузера нет прямого доступа к MinIO.

2. **Вынести общие правила загрузки в плагин хранения.** Применять одинаковую проверку пути, имени, расширения, содержимого и размеров. Если модулям нужны разные форматы или лимиты, описать их в явных профилях. Сначала перенести правила документов поставок с сохранением принятого поведения, затем согласовать профили остальных источников. Относительные пути при загрузке целой папки используются для создания записей папок в PostgreSQL. Ключ MinIO формируется из серверных идентификаторов.

3. **Унифицировать скачивание.** Каждый модуль принимает идентификатор файла, проверяет доступ к исходной карточке и папке, находит ключ в своей таблице и передаёт его общему сервису. Сервис открывает поток и применяет общие правила заголовков, имён и предпросмотра. Для штатных вложений сохранить совместимый `fileStorage:open` и подписанные ссылки. Для таких ссылок оставить короткий срок жизни и проверять права при выдаче ссылки. Для документов с проверкой прав на каждый запрос сохранить это требование. Существующие экраны и API подключить к общему сервису через свои адаптеры.

4. **Сделать сбои загрузки и удаления предсказуемыми.** Если файл записан в MinIO, а транзакция PostgreSQL откатилась, удалить только объект, созданный этой попыткой. После удаления документа очищать объект после фиксации изменения в БД. Если хранилище недоступно, операцию очистки должно быть возможно повторить без удаления чужих файлов. Повтор загрузки из-за сетевого сбоя не должен затирать ранее загруженный объект. Совместимое чтение из старых областей держать в адаптере хранения.

5. **Подключить источники по очереди.** Сначала переключить `plugin-process-documents`. Проверить рейсы, поставки и учредительные папки на одном и том же сервисе. Затем переключить `log-company-private-minio` и проверить существующие вложения компаний, разрешительных документов и обсуждений. Чаты подключить отдельным этапом с проверкой доступа участников. Их участие касается серверного хранения. В файловом менеджере компаний чаты по-прежнему исключены.

Общий сервис хранит объекты. Права определяются в месте, где файл используется. В частности, разрешение на исходную запись само по себе не открывает закрытую папку, а разрешение на папку не выдаёт доступ к чужой компании.

## Как перейти на новый сервис

Начать с переключения операций на общий сервис при сохранении действующих ключей и таблиц. Такое изменение не требует переносить содержимое бакета. Старые записи, документы черновиков и уже выпущенные ссылки проверить отдельно. Если позднее действительно понадобится новый формат ключей, оформить отдельную миграцию с копированием, проверкой контрольных сумм и переключением ссылок после проверки. Исходные объекты сохранить на период отката.

Сначала собрать, установить и проверить новую совместимую версию `plugin-file-storage` на тестовом контуре. Затем обновлять плагины-потребители по одному. Перед обновлением рабочей CRM подготовить согласованные резервные копии PostgreSQL и MinIO, сохранить предыдущие пакеты плагинов и ключ подписи файловых ссылок. Использовать штатный менеджер плагинов NocoBase. Порядок сборки и установки описан в [FILE_STORAGE.md](FILE_STORAGE.md).

## Что проверить перед выпуском

| Сценарий | Ожидаемый результат |
| --- | --- |
| Загрузка файла или готовой папки | Файлы появляются в нужной карточке и в общем каталоге, подпапки сохранены. |
| Одна поставка в двух рейсах | Обе ветки показывают один набор документов. Переименование папки сохраняет доступ к файлам. |
| Разные компании, роли и персональные разрешения | Недоступный файл нельзя открыть по идентификатору. Проверка действует и для вложенной папки, открытой по прямой ссылке. |
| Существующие вложения и ссылки | Старые документы открываются. Ссылка с истёкшим сроком отклоняется. |
| Неверный формат, превышение лимита или ошибка MinIO | Пользователь получает понятную ошибку. Частичная загрузка не оставляет доступной битой записи. |
| Откат записи в БД, повтор операции или сбой при удалении | Очистку можно завершить повторно, существующие объекты не повреждаются. |
| Чат после переключения его адаптера | Участники открывают свои вложения через чат. В каталоге компаний эти вложения отсутствуют. |
