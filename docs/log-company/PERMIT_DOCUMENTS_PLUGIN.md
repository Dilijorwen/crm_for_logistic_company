# @log-company/plugin-permit-documents

## Назначение

Плагин хранит ДС, СС и СГР в коллекции `permit_documents`, при необходимости связывает документ с одной записью
`our_companies` и автоматически проверяет сведения в реестрах Росаккредитации и ЕАЭС. Одна компания может иметь
несколько разрешительных документов, а документ можно создать без компании.

## Модель данных

Пользователь заполняет номер (`title`) и тип (`document_type`), а также при необходимости компанию (`company`) и
вложения (`documents`). Поле `name` формируется автоматически и является title-полем коллекции. Остальные поля
управляются синхронизацией.

Названия коллекций, колонок и значения перечислений отображаются на русском независимо от локали пользователя.
Системный интерфейс настройки NocoBase и название добавляемого действия используют выбранную локаль интерфейса.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `title` | string | Номер документа и часть уникальной идентичности |
| `name` | string | Автоматическое название и title-поле коллекции |
| `document_type` | select | `ДС`, `СС` или `СГР` |
| `company` / `company_id` | belongs-to, nullable | Необязательная ссылка на `our_companies.id` |
| `valid_from` | date-only, nullable | Дата регистрации |
| `valid_until` | date-only, nullable | Окончание действия; может отсутствовать у СГР и документов FSA на единичное изделие |
| `status` | select, nullable | `Действителен`, `Приостановлен` или `Прекращен` |
| `product_information` | text, nullable | Сведения о продукции из реестра |
| `external_id` | string, nullable | ID карточки FSA либо UUID ЕАЭС/SWIS |
| `external_status` | string, nullable | Исходный статус внешнего реестра |
| `sync_status` | select | `PENDING`, `SUCCESS`, `NOT_FOUND` или `ERROR` |
| `last_checked_at` | datetime, nullable | Время последней завершённой проверки |
| `last_sync_error` | text, nullable | Безопасный машинный код ошибки |
| `technical_regulations` | belongs-to-many | Единый справочник применимых ТР |
| `documents` | attachments | Пользовательские файлы документа |

Для `SUCCESS` обязательны дата регистрации и сведения о продукции. Дата окончания сохраняется, когда она есть в
реестре; для СГР и некоторых документов FSA на единичное изделие она отсутствует.
При остальных состояниях реестровые поля могут быть пустыми. Пара `(document_type, title)` уникальна во всей системе.
После успешной синхронизации название документа со сроком действия имеет вид
`НОМЕР от ДД.ММ.ГГГГ до ДД.ММ.ГГГГ`, а без даты окончания — `НОМЕР от ДД.ММ.ГГГГ`. До получения даты регистрации
название равно номеру документа.

Справочник `technical_regulations` содержит уникальные `doc_num` и nullable-уникальный `fsa_id`. Связь M:N хранится в
`document_technical_regulations` с уникальной парой документа и ТР.

## Синхронизация

- изменение полей формы само по себе не запускает запрос к реестру;
- после успешного Submit создания или изменения номера/типа документ получает `PENDING`, старые реестровые поля и
  связи очищаются, затем выполняется синхронизация до завершения API-запроса; поэтому штатное обновление таблицы после
  сохранения сразу получает итоговые реестровые данные;
- смена только компании не вызывает внешний запрос;
- ДС и СС, направляемые в FSA, получают краткоживущий Bearer через FSA login; токен хранится только в памяти и обновляется после `401`;
- СГР использует московскую календарную дату при каждом запросе;
- СС и ДС с кодом страны `KG` в номере проверяются в публичном HTML-реестре `swis.trade.kg`:
  `/Registry/CertificateOfConformity` и `/Registry/DeclarationOfConformity` служат источником номера, статуса, дат,
  сведений о продукции и UUID, а `/Doc/{UUID}` используется только для технических регламентов;
- полная синхронизация при создании, смене номера/типа и действии «Проверить сейчас» перезаписывает название, даты,
  сведения о продукции, статус и технические регламенты; для ДС/СС сведения о продукции собираются из всех
  `product.identifications[].name` в порядке ответа FSA;
- ежедневная проверка использует только поисковый ответ реестра и обновляет статус, исходный статус и служебные поля
  проверки, не загружая полную карточку и не перезаписывая остальные данные;
- временные HTTP-ошибки повторяются три раза с backoff, затем получают `ERROR` и повторяются следующим ежедневным
  запуском;
- `NOT_FOUND` повторяется только после смены номера/типа или команды «Проверить сейчас»;
- ручная проверка ждёт окончательного ответа реестра, после записи результата вызывает штатный `refreshAsync()`
  текущего data block и полностью перезагружает текущий блок таблицы;
- cron запускается в `00:00` по `Asia/Vladivostok` и не проверяет документы в статусе `Прекращен`; документы `ERROR`
  без внешнего ID повторяют полную синхронизацию, а документы с внешним ID проходят облегчённую проверку статуса;
- обновление документа, справочника ТР и M:N-связей выполняется атомарно.

Подробная архитектура описана в [PERMIT_DOCUMENT_SYNC_DESIGN.md](PERMIT_DOCUMENT_SYNC_DESIGN.md).

## Конфигурация

Production требует `FSA_USERNAME` и `FSA_PASSWORD`. Значения не включаются в исходный код. Опциональные переменные:

```dotenv
FSA_BASE_URL=https://pub.fsa.gov.ru
EAEU_BASE_URL=https://nsi.eaeunion.org
SWIS_BASE_URL=https://swis.trade.kg
```

Права на документы, справочник ТР и действие синхронизации настраиваются стандартным ACL NocoBase. Действие
«Проверить сейчас» наследует object-level ограничения `update`. В таблице оно добавляется в колонку действий через
`Configure actions` → `Check now` (`Настроить действия` → `Проверить сейчас`).

## Установка и проверка

```bash
yarn build @log-company/plugin-permit-documents --only
yarn tar @log-company/plugin-permit-documents
yarn nocobase pm add @log-company/plugin-permit-documents
yarn nocobase pm enable @log-company/plugin-permit-documents
yarn nocobase upgrade
```

Миграция `20260828010000-add-registry-synchronization` добавляет технические поля, справочник и M:N, переносит старый
`revoked` в `terminated`, создаёт ограничения и удаляет legacy-поле `technical_regulation` из метаданных. Физическая
legacy-колонка намеренно остаётся нетронутой для безопасного отката и не используется приложением.
Миграция `20260828020000-sync-permit-document-metadata` обновляет существующие метаданные полей NocoBase и
идемпотентно проверяет уникальные индексы справочника ТР.
Миграция `20260907010000-make-permit-document-company-optional` разрешает `NULL` в `company_id` и убирает обязательность
поля компании из метаданных формы NocoBase.
Миграция `20260908010000-sync-optional-company-metadata` обновляет скрытые метаданные внешнего ключа `company_id`,
чтобы серверная Sequelize-модель также разрешала создание документа без компании.
Миграция `20260908020000-disable-fsa-id-thousands-separator` отключает разделитель тысяч при отображении числовых ID
технических регламентов.
Миграция `20260916010000-add-permit-document-name` добавляет и заполняет поле `name`, а затем назначает его title-полем
коллекции.
Миграция `20260916020000-allow-open-ended-fsa-documents` разрешает успешную синхронизацию ДС/СС без даты окончания,
если реестр не задаёт срок действия документа.
