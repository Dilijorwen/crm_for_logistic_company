# Отчёт о переходе CRM на FSD и Onion

## Выполнено

Frontend девяти собственных плагинов организован по FSD. Backend сохраняет Onion, технические зависимости убраны из внутренних слоёв. Добавлены независимые DTO, раздельные проверки типов и автоматические проверки импортов. Точки входа плагинов, API, дизайн и бизнес-сущности сохранены.

## Архитектурные решения

- Единица установки — существующий плагин NocoBase. Разделение frontend/backend выполнено через код, DTO и проверки; отдельные приложения/контейнеры не вводились.
- FSD адаптирован к блокам конструктора: блоки находятся в widgets; существующие самостоятельные страницы — в pages. Пустые слои не создаются.
- Domain/application независимы от NocoBase, HTTP, ORM, MinIO и Node.js API. Зависимости собираются во внешнем кольце.
- Новые зависимости и обновления версий не понадобились. Полная карта: [ARCHITECTURE.md](ARCHITECTURE.md).

## База данных

Таблицы, поля, индексы, связи и миграции не изменялись. Рабочие данные и пользовательский .env не менялись. Серверные проверки использовали изолированные SQLite-базы; созданные ими временные файлы удалены.

## Неустранённые ограничения

- Opt-in integration-тесты реальных PostgreSQL/MinIO не включались; запуск выполнялся с SQLite и тестовыми адаптерами.
- Собранные пакеты не установлены в рабочий контейнер. Проверка UI в браузере на обновлённом runtime и production-миграции не выполнялись.
- Разделение выполнено внутри NocoBase. Для независимого frontend-приложения потребуется отдельная задача по маршрутам, авторизации и интеграции конструктора.
