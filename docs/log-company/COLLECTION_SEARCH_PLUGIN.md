# Поиск по текущей коллекции

Плагин `@log-company/plugin-collection-search` добавляет в табличный блок NocoBase действие быстрого
поиска. Действие не привязано к конкретной коллекции: коллекция и её текущий `table resource`
определяются из контекста блока.

## Поведение в таблице

Поисковая строка располагается среди действий таблицы. Отдельного окна, отдельного списка
результатов и собственной пагинации нет. При поиске меняется только серверное действие обновления
текущего ресурса таблицы:

```text
CollectionSearchActionModel
  -> <collection>:searchCurrentCollection
  -> индекс lc_collection_search_documents
  -> стандартный actions.list исходной коллекции
  -> текущий MultiRecordResource
  -> стандартная таблица NocoBase
```

Поэтому таблица сохраняет настроенные колонки, форматирование, действия строк, сортировку,
постраничную навигацию и фильтры блока.

Поиск запускается начиная с трёх символов. Ввод обрабатывается с задержкой 325 мс, а Enter запускает
допустимый запрос сразу. При очистке или сокращении запроса до одного-двух символов ресурс
возвращается к стандартному действию `list` и к первой странице. Предыдущий запрос отменяется;
ответ с устаревшим порядковым номером не применяется к таблице. Пока пользователь вводит первый и
второй символ нового запроса, ресурс таблицы не обновляется, поэтому строка поиска не теряет фокус.
Фокус также сохраняется после получения результатов: перерисовка таблицы не сбрасывает состояние
активного поиска. Очистка строки после такой перерисовки всегда возвращает ресурс к обычному `list`.
Если допустимый запрос сокращается до одного-двух символов, таблица возвращается к `list`, но
оставшийся набранный текст сохраняется в строке и может быть продолжен или удалён пользователем.

## Какие данные индексируются

Индекс строится по всей коллекции, а не по колонкам текущего table block. Поэтому текстовое поле,
не добавленное в таблицу, участвует в поиске наравне с видимой колонкой.

Поддерживаются:

- строки и многострочный текст;
- числа;
- даты в исходном и читаемом формате;
- логические значения;
- подписи вариантов выбора вместе с их хранимыми значениями;
- отображаемые значения связей.

Первичные и внешние ключи, пароли, файлы и поля без пригодного пользовательского представления не
индексируются. Для связи используется `titleField` целевой коллекции, если это обычное пригодное для
поиска поле. Для связей с несколькими значениями в документ попадают все отображаемые значения.

Например, поставка `1/Азия/INV-5328/ЗВ-102/ДТ-555` находится по `Азия`, `INV`, `532`, `102` и `555`,
а рейс может быть найден по номеру машины, клиенту, поставке, менеджеру, декларанту или городу,
если соответствующая связь входит в модель коллекции и имеет `titleField`.

## Индекс и актуализация

Для каждой записи хранится один документ в `lc_collection_search_documents`:

- `keyValues` — ключ исходной записи для корреляции;
- `fieldValues` — поисковые значения по полям, необходимые для применения полевого ACL;
- `searchText` — объединённый текст документа.

В PostgreSQL используется `pg_trgm` и GIN-индекс `gin_trgm_ops` по `searchText`. Сначала PostgreSQL
получает кандидатов по индексированному `ILIKE '%term%'`, затем проверяет совпадение только в полях,
доступных текущему пользователю. В исходный запрос добавляется коррелированный `EXISTS`; список ID
не передаётся клиенту и не превращается в большой `IN (...)`.

Индекс коллекции создаётся лениво при первом поиске. Сигнатура учитывает скалярные поля, пути связей
и их `titleField`, поэтому изменение схемы приводит к перестроению при следующем поиске. Подписчик
обновляет документ после создания, изменения и удаления исходной записи. Для индексируемых связей
он также отслеживает изменение и удаление целевой записи и изменение промежуточной таблицы
many-to-many, после чего перечитывает затронутые исходные записи с нужными `appends`.

## ACL, фильтры и пагинация

Действие `searchCurrentCollection` является ACL-псевдонимом стандартного `view`. Оно не читает
исходные записи самостоятельно: после добавления индексного условия вызывается стандартный
`actions.list`. Поэтому действуют обычные ограничения NocoBase на записи и поля, текущий фильтр
таблицы, сортировка, `page` и `pageSize`.

Разрешённые поля берутся из результата ACL-проверки текущего запроса. Даже если поисковый документ
содержит больше данных, условие по `fieldValues` учитывает только разрешённые поля и не позволяет
найти запись по закрытому значению.

## Настройка действия

Действие добавляется в таблицу штатным конструктором FlowEngine под названием **«Поиск по
коллекции»**. Настройки хранятся в самой FlowEngine-модели; отдельной таблицы настроек нет.

Доступны параметры, которые действительно меняют поведение действия:

- поля коллекции, по которым выполняется поиск;
- подсказка поисковой строки;
- ширина поисковой строки.

По умолчанию выбраны все пользовательски значимые поля коллекции. В настройке не показываются
первичные и внешние ключи, пароли, файлы и другие технические поля. Выбор ограничивает поиск, но не
изменяет состав общего поискового индекса. Сервер дополнительно пересекает выбранные поля с текущим
полевым ACL пользователя.

Использовать строку поиска могут все пользователи с правом просмотра коллекции. Меню настройки
этого действия отображается только при текущей роли `root`. Дополнительно серверный middleware
проверяет изменяющие запросы `flowModels`: обычный пользователь не может создать, изменить,
переместить, дублировать или удалить модель поиска, в том числе через изменение содержащего её
поддерева. Таким образом, ограничение не сводится к скрытию кнопки в интерфейсе.

## Миграция со старой версии

Миграция удаляет из FlowEngine старые экземпляры `CollectionSearchBlockModel`. Модель действия
`CollectionSearchActionModel` сохраняется и теперь отображает строку поиска непосредственно в
панели действий таблицы. После обновления второго пользовательского варианта поиска не остаётся.

Таблицы поисковых документов и состояний, расширение `pg_trgm` и GIN-индекс сохраняются. Изменение
сигнатуры схемы заставляет существующие коллекции безопасно перестроить документы с данными связей
при первом новом запросе.

## Ограничения

- Индексированный запрос рассчитан на PostgreSQL и требует, чтобы исходная коллекция и таблица
  поискового индекса использовали одно PostgreSQL-подключение. Коллекции из внешнего источника с
  отдельным подключением этим оператором не обслуживаются.
- Для связи индексируется только `titleField` первого уровня. Рекурсивный обход графа связей
  намеренно не выполняется.
- Первое построение индекса большой коллекции выполняется синхронно с первым поиском и может занять
  заметное время; последующие изменения обновляются инкрементально.
