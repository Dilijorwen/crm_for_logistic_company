# Документы поставки

Плагин `@log-company/plugin-process-documents` версии `2.0.61` предоставляет самостоятельный блок
`Документы поставки`. Пользователь добавляет его в popup или форму коллекции `shipments` через конструктор NocoBase.
Плагин не создаёт готовую страницу и не меняет её компоновку.

Исходники в `packages/plugins/@log-company/plugin-process-documents` являются единственным источником истины.
Установленную копию в `storage/plugins` вручную не редактируют.

## Модель данных

Сохраняются две коллекции с историческими техническими именами:

### `process_document_folders`

- `id`, `title`;
- `shipment_id` — текущая необязательная ссылка на `shipments.id`;
- `parent_folder_id` — родительская папка;
- `draft_token` — область документов ещё не сохранённой поставки;
- скрытый `process_id` оставлен только для совместимости со старыми данными;
- стандартные поля автора и времени.

### `process_documents`

- `id`, `title`, `original_filename`;
- `shipment_id` — текущая необязательная ссылка на `shipments.id`;
- `folder_id`, `draft_token`;
- `storage_key`, `mime_type`, `file_size`;
- скрытый `process_id` оставлен только для совместимости со старыми данными;
- стандартные поля автора и времени.

Оба `shipment_id` имеют индекс и внешний ключ на `shipments.id` с `ON DELETE CASCADE`. Старые `process_id` и
связанные с ними записи не удаляются и автоматически не переносятся: для такого переноса нужно отдельно определить,
какой прежний таможенный процесс соответствует какой поставке.

## Область документов

В существующей записи API получает `shipmentId` и проверяет наличие поставки и объектный ACL. В форме создания блок
использует `draftToken`; после успешного `shipments:create` клиент и сервер прикрепляют draft к новой поставке.

Текущие объекты MinIO получают безопасные ключи:

```text
shipments/{shipment_id}/{uuid}.{extension}
shipments/drafts/{draft_token}/{uuid}.{extension}
```

Имя, показанное пользователю, хранится отдельно в `title` и `original_filename`. Старые объекты с префиксом
`processes/` остаются без изменений.

## Возможности блока

- загрузка одного или нескольких файлов;
- загрузка дерева папки через `webkitdirectory`;
- вложенные папки и breadcrumbs;
- автоматические суффиксы для одноимённых папок и файлов без перезаписи;
- скачивание через сервер NocoBase;
- удаление файла;
- подтверждаемое рекурсивное удаление папки;
- draft-загрузка до первого сохранения поставки.

Внешнее имя API `processDocuments` сохранено для обратной совместимости. Actions: `list`, `createFolder`,
`uploadFiles`, `download`, `deleteFile`, `folderDeleteSummary`, `deleteFolder`.

Клиент не получает постоянные ссылки или учётные данные MinIO. Сервер проверяет, что папка, файл и родитель относятся
к одной поставке или одному draft, запрещает самоссылки и циклы и выполняет связанные операции транзакционно.

## Удаление поставки

Удаление самой поставки разрешается только после открепления от всех рейсов. После разрешённого удаления плагин:

1. находит документы и папки по `shipment_id`;
2. удаляет их записи в той же транзакции;
3. после commit удаляет MinIO-объекты с префиксом `shipments/{shipment_id}/`;
4. при rollback сохраняет файлы и записи согласованными.

Удаление поставки не затрагивает старые документы с заполненным только `process_id`.

## ACL

Чтение требует доступа к записи `shipments` и к коллекциям документов. Изменение требует update-доступа к конкретной
поставке и соответствующего `create`/`destroy` для документов или папок. Draft доступен только его владельцу.

Все подписи нового интерфейса и сообщения ошибок заданы непосредственно на русском языке, без i18n.

## MinIO

Приложение обращается к MinIO внутри Docker-сети по `http://minio:9000`. Bucket по умолчанию:
`log-company-process-documents`. Постоянные данные находятся в `storage/minio`; NocoBase и MinIO наружу не передают
секретные ключи клиенту.

## Сборка и обновление

```bash
yarn eslint --fix packages/plugins/@log-company/plugin-process-documents/src
yarn build @log-company/plugin-process-documents
yarn tar @log-company/plugin-process-documents
docker compose exec -T app yarn pm update /app/nocobase/storage/tar/@log-company/plugin-process-documents-2.0.61.tgz
docker compose exec -T app yarn nocobase upgrade
docker compose restart app
```

После обновления проверяют пустой блок существующей поставки, draft в форме создания, загрузку, скачивание, удаление
файла и папки, а также каскад при удалении несвязанной с рейсами поставки.
