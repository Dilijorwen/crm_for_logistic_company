# Блок «Документы»

Самостоятельный блок **«Документы»** из `@log-company/plugin-process-documents` добавляется в карточку или форму
через конструктор NocoBase. Уже добавленные блоки «Документы поставки» используют ту же модель.

- В поставке доступны файлы, папки и черновик до первого сохранения.
- В общей форме создания процесса файлы новой поставки можно загрузить в папки «Декларанты» и «Менеджеры».
  Они появляются в разделе «Файлы» после сохранения рейса и поставки. Закрытие формы
  или удаление новой поставки до сохранения отменяет загрузку.
- В компании блок открывает папку «По запросу / Учредительные документы».
- В сохранённом рейсе блок открывает один общий комплект документов. В каталоге «Файлы» этот комплект доступен в папке
  каждой компании, чья поставка привязана к рейсу. В каждой ветке видны только поставки текущей компании.
- В разрешительном документе используется штатное поле «Документы». В другой коллекции блок использует поле типа
  «Вложение» с целью `attachments` для просмотра. Если подходящих полей несколько, их можно переключать.

В общей форме рейс и поставка используют один интерфейс документов с действиями «Загрузить» и «Новая папка».
В форме создания выбранные файлы и созданные папки появляются в хранилище после сохранения процесса.
В сохранённой карточке действия с документами применяются сразу с учётом прав доступа.
В общей форме редактирования загрузка и создание папок доступны в корне документов рейса и внутри его папок.
В документах поставки эти действия доступны внутри существующих папок.

Пустая сохранённая карточка показывает «Документов пока нет». В поддерживаемых формах создания и редактирования
файлы можно выбрать сразу, в том числе до первого сохранения.

### Автоматические режимы «Просмотр» и «Загрузка»

В настройках блока **«Документы» → «Режим»** выберите только режим. Компания и папка вручную не задаются.

| Карточка | Что открывает блок |
| --- | --- |
| Рейс | Документы этого рейса. В «Файлах» один и тот же рейс появляется у всех связанных компаний; внутри каждой ветки видны только её поставки. |
| Поставка | Документы этой поставки, общие для всех её рейсов. |
| Разрешительный документ | Штатное поле «Документы». Новые файлы, добавленные через блок, хранятся в MinIO. |
| Компания | «Компания / По запросу / Учредительные документы». |
| Контракт | Основной документ сохраняется в поле «Документы» самого контракта. Для загрузки из формы нужна одна связанная компания. Дополнительные соглашения загружаются из файлового менеджера. |

Файловый менеджер показывает «По запросу» и «Учредительные документы» даже без файлов. При первой успешной
загрузке из карточки сервер сохраняет нужные папки, и оба экрана открывают их по ID.
Существующее название «По запросам» также
поддерживается. Если найдено несколько подходящих папок на одном уровне, загрузка сообщает о конфликте.
Файлы, ранее загруженные в общую папку или в пользовательские подпапки, доступны по прежним путям в файловом менеджере.

Файл связан с папкой по `folder_id` и с компанией по `company_id`. При скачивании сервер находит документ
по его ID и читает сохранённый `storage_key`. Для этого раздела ключ имеет формат
`v1/<application>/process-documents/companies/<companyId>/company/<uuid>.<extension>`.
Контракт определяет компанию по связи с записью компании. Названия папок в ключ объекта не входят.

- **Просмотр** показывает документы без загрузки и переименования. Для сохранённых рейсов и поставок действие
  «Удалить» доступно только по правам файлового менеджера. До первого сохранения записи списка ещё нет.
- **Загрузка** показывает те же документы. Кнопки выбора, черновик и сохранённые документы находятся в одном списке.
  При перетаскивании блок сам распознаёт файлы и папки. В списках рейсов и поставок сброс на строку папки
  направляет загрузку в неё, а сброс на остальную область — в текущую папку. Поместите блок в
  то же окно, что и одну штатную форму создания или редактирования одной записи основного источника данных.
  В режиме редактирования соседний блок ищет форму в той же вкладке и проверяет, что она открыта для той же записи.
  Добавленные файлы хранятся во временной папке сервера и публикуются вместе с успешным сохранением формы. При
  отмене или очистке черновика временные файлы удаляются. При ошибке сохранения их можно отправить повторно.

Режимы выбираются в конструкторе. Если режим не задан, блок рядом со штатной формой создания или редактирования
рейса, поставки, компании, контракта или разрешительного документа по умолчанию использует «Загрузку».
В остальных карточках без выбранного режима используется «Просмотр». Для существующего блока поставки без режима
и без связанной формы оставлено прежнее поведение.
В рабочем списке загрузка в форме рейса и в отдельной форме поставки завершается при сохранении соответствующей
формы. В общей карточке рейса раздел «Документы поставки» показывает папку выбранной сохранённой поставки.
Загруженные в этот раздел файлы и папки сохраняются сразу с учётом прав на поставку и папку.
При создании поставки отдельно или внутри формы рейса в её корне появляются папки «Менеджеры», «Декларанты», «Бухгалтерия»,
«Юристы» и «Карго». Для уже существующих поставок папки автоматически не добавляются.
Временный черновик рассчитан на один процесс приложения:
при перезапуске сервера файлы нужно выбрать заново. При закрытии вкладки без ответа сервера срабатывает очистка
по истечении двух часов. Структура папок с файлами сохраняется. В черновиках рейсов и поставок при
перетаскивании сохраняются и пустые папки; в остальных черновиках пустые папки не переносятся.
В разрешительных документах вложенность показывается в блоке «Документы»; штатное поле по-прежнему содержит те же вложения.

Блок «Документы» принимает до 500 МБ на файл, до 2500 МБ файлов и до 1000 файлов и пустых папок за одну загрузку.
Разрешено до 200 частей пути, включая имя файла, по 200 символов на часть. Имена и пути передаются отдельным полем UTF-8.
Лимиты 2500 МБ и 1000 элементов также применяются к активным черновикам одного пользователя, а суммарный объём
сохранённых черновиков всех пользователей ограничен 10 ГБ на процесс приложения. Штатные вложения CRM используют
свои лимиты. На сервере прокси должен пропускать multipart-запросы с учётом метаданных (до 2628 МБ).

В блоке «Документы» списки файлов в папках и списки штатных вложений оформлены одинаково. Имя файла открывает
просмотр в карточке, действие «Скачать» доступно отдельно. Разделы и права на загрузку и удаление остаются раздельными.
Excel (`.xlsx`, `.xls`), ODS и CSV открываются как таблицы.
Для PDF, изображений и мультимедиа используется просмотр браузера, для DOCX, ODT и PPTX показывается текст.
Файлы не передаются внешним сервисам. Для форматов без предпросмотра в том же окне доступно скачивание.

Кнопка **«Удалить»** требует подтверждения и удаляет вложение из карточки и хранилища. В MinIO удаление выполняется
очередью после сохранения изменения в БД; при сбое операция повторяется. Если то же вложение используется ещё в одной
карточке, удаление блокируется. Для штатных вложений сервер проверяет права изменения поля карточки и удаления файла.

Исходники в `packages/plugins/@log-company/plugin-process-documents` являются единственным источником истины.
Установленную копию в `storage/plugins` вручную не редактируют.

## Модель данных

Сохраняются две коллекции с историческими техническими именами:

### `process_document_folders`

- `id`, `title`;
- `shipment_id` — текущая необязательная ссылка на `shipments.id`;
- `parent_folder_id` — родительская папка;
- `draft_token` — область документов ещё не сохранённой поставки;
- скрытый `process_id` оставлен только для совместимости со старыми данными;
- стандартные поля автора и времени.

### `process_documents`

- `id`, `title`, `original_filename`;
- `shipment_id` — текущая необязательная ссылка на `shipments.id`;
- `folder_id`, `draft_token`;
- `storage_key`, `mime_type`, `file_size`;
- скрытый `process_id` оставлен только для совместимости со старыми данными;
- стандартные поля автора и времени.

Оба `shipment_id` имеют индекс и внешний ключ на `shipments.id` с `ON DELETE CASCADE`. Старые `process_id` и
связанные с ними записи не удаляются и автоматически не переносятся: для такого переноса нужно отдельно определить,
какой прежний таможенный процесс соответствует какой поставке.

## Область документов

В существующей записи API получает `shipmentId` и проверяет наличие поставки и объектный ACL. В форме создания блок
использует `draftToken`; после успешного `shipments:create` клиент и сервер прикрепляют draft к новой поставке.

Текущие объекты MinIO получают безопасные ключи:

```text
shipments/{shipment_id}/{uuid}.{extension}
shipments/drafts/{draft_token}/{uuid}.{extension}
```

Имя, показанное пользователю, хранится отдельно в `title` и `original_filename`. Старые объекты с префиксом
`processes/` остаются без изменений.

## Возможности блока

- загрузка одного или нескольких файлов;
- загрузка дерева папки через `webkitdirectory`;
- вложенные папки и breadcrumbs;
- автоматические суффиксы для одноимённых папок и файлов без перезаписи;
- скачивание через сервер NocoBase;
- удаление файла;
- подтверждаемое рекурсивное удаление папки;
- draft-загрузка до первого сохранения поставки.

Внешнее имя API `processDocuments` сохранено для обратной совместимости. Actions: `list`, `createFolder`,
`uploadFiles`, `download`, `deleteFile`, `folderDeleteSummary`, `deleteFolder`.
Для штатного вложения используется `POST processDocuments:deleteAttachment` с полями `collection`, `recordId`,
`field` и `attachmentId`. Удаление вне указанной связи запрещено, для общего вложения сервер возвращает 409.

Клиент не получает постоянные ссылки или учётные данные MinIO. Сервер проверяет, что папка, файл и родитель относятся
к одной поставке или одному draft, запрещает самоссылки и циклы и выполняет связанные операции транзакционно.

## Удаление поставки

Удаление самой поставки разрешается только после открепления от всех рейсов. После разрешённого удаления плагин:

1. находит документы и папки по `shipment_id`;
2. удаляет их записи в той же транзакции;
3. после commit удаляет MinIO-объекты с префиксом `shipments/{shipment_id}/`;
4. при rollback сохраняет файлы и записи согласованными.

Удаление поставки не затрагивает старые документы с заполненным только `process_id`.

## ACL

Для просмотра и удаления документов поставки или рейса нужен доступ на просмотр конкретной записи. Право удалять
файлы и папки отдельно выдаёт администратор в **«Файловый менеджер → Права на документы → ВЭД → Удаление»**.
По умолчанию оно выключено: после обновления проверьте, что у нужных ролей или сотрудников сохранено явное разрешение.
Учитываются ограничения всей цепочки папок, а для общего комплекта рейса — правила всех связанных компаний.
Перед удалением папки сервер также проверяет права во всех вложенных папках. В каталоге файлового менеджера и в блоке
«Документы» сохранённого рейса или поставки действие «Удалить» отображается по этим правам независимо от режима.
Право на удаление файла не даёт прав на изменение или удаление самой записи.
Для загрузки и переименования по-прежнему проверяется право изменения записи. Draft доступен только его владельцу.

Все подписи нового интерфейса и сообщения ошибок заданы непосредственно на русском языке, без i18n.

## MinIO

Приложение использует единый закрытый bucket `log-company-files` и общую конфигурацию из
[FILE_STORAGE.md](FILE_STORAGE.md). Логические ключи автоматически получают префикс
`v1/<application>/process-documents/`. Прежний bucket сохраняется как источник безопасного переноса и совместимого
чтения. Постоянные данные находятся в `storage/minio`; секретные ключи клиенту не передаются.

## Сборка и обновление

```bash
yarn eslint --fix packages/plugins/@log-company/plugin-process-documents/src
export PLUGIN_PACKAGE_PREFIX=@nocobase/plugin-,@nocobase/preset-,@nocobase/plugin-pro-,@log-company/plugin-
yarn build @log-company/plugin-file-storage @log-company/plugin-process-documents
yarn tar @log-company/plugin-file-storage @log-company/plugin-process-documents
docker compose exec -T app yarn pm update /app/nocobase/storage/tar/@log-company/plugin-file-storage-2.0.61.tgz
docker compose exec -T app yarn pm update /app/nocobase/storage/tar/@log-company/plugin-process-documents-2.0.110.tgz
docker compose exec -T app yarn nocobase upgrade
docker compose restart app
```

После обновления архива проверьте, что перезапустился именно веб-процесс NocoBase. Если он запущен напрямую в контейнере,
внутренний вызов PM2 из `pm update` его не перезапустит. До перезапуска `pm:listEnabled` может выдавать прежний
хэш клиентского скрипта, и браузер продолжит использовать кеш даже при новой версии на диске.
Сборка «Документов» использует установленный `plugin-file-storage`. При сборке поверх старого `dist` проверьте,
что в архив не попала устаревшая копия по пути `dist/node_modules/@log-company/plugin-file-storage`:
она перекрывает установленную версию. Если копия осталась от старой сборки, отложите её вне `dist` и пересоберите архив.

После обновления проверяют пустой блок существующей поставки, draft в форме создания, загрузку, скачивание, удаление
файла и папки, а также каскад при удалении несвязанной с рейсами поставки.

## Файловый менеджер компаний

В конструкторе добавьте блок **«Файловый менеджер»**. Режим **«Все доступные компании»** открывает общий каталог.
В настройках можно включить **«Открывать в отдельном окне»**. В карточке компании, поставки или рейса используйте
**«По текущей карточке»**. Блок можно ограничить просмотром.

```text
Компания Альфа/ВЭД/2026/Ноябрь/Рейс №87 - А123ВС/Декларантам/СМР.pdf
Компания Альфа/ВЭД/2026/Ноябрь/Рейс №87 - А123ВС/Поставка №1042/Декларантам/Инвойс.pdf
Компания Альфа/Разрешительные документы/Действителен/142/Скан.pdf
Компания Альфа/Разрешительные документы/Приостановлен/143/СС/Скан.pdf
Компания Альфа/По запросу/Учредительные документы/Регистрационные/Устав.pdf
Компания Альфа/Контракты/Действующий/2283/Контракт.pdf
Компания Альфа/Контракты/Действующий/2283/Доп. соглашение/Соглашение.pdf
```

- Номера рейса, машины и поставки подставляются по существующим связям. Год и месяц рейса берутся из самой ранней
  даты создания связанной поставки. Если поставка есть в нескольких рейсах, в каждой ветке отображаются те же файлы.
  Поставки без связанного рейса доступны в отдельной папке ВЭД.
- В общем каталоге ВЭД доступен просмотр файлов и папок рейсов и поставок. Загрузка выполняется в таможенном
  оформлении. У рейса одна папка документов, которая видна в связанных ветках.
- «Разрешительные документы» доступны для просмотра. Ранее загруженные в корне файлы остаются видимыми по
  правам раздела. Вложения из карточек разрешительных документов каталог группирует по статусам
  «Действителен», «Приостановлен», «Прекращен», затем по внутреннему номеру. Если в группе несколько типов,
  появляются папки ДС, СС и СГР для присутствующих типов. Файлы одного типа лежат прямо в папке номера.
- Загрузка файлов и готовых папок доступна сразу в папке компании. В область списка можно перетащить файлы и папки
  одновременно. Папки сохраняют вложенность, включая пустые папки, если браузер передаёт структуру каталога.
  Кнопки «Загрузить» и «Новая папка» доступны там же. Учредительные документы из карточки компании
  видны в «По запросу / Учредительные документы». В «По запросу» файлы или подпапки можно добавить при первом
  открытии, в том числе когда этот путь ещё пуст.
- Контракты группируются по фактическому статусу и связи с компанией. Основные документы берутся из карточки
  контракта, а в каталоге блок действий загрузки доступен в папке «Доп. соглашение». Старые файлы в общей папке
  «По запросу / Контракт» сохранены, поскольку их записи не содержат ID конкретного контракта.
- Для вывода содержимого одной папки выберите **«Конкретная папка компании»** или
  **«Конкретная папка учредительных документов»** и укажите ID компании и папки. ID доступен администратору в правах папки.

Суперпользователь открывает **«Права на документы»** из списка компаний или корня конкретной компании.
В шапке каталога рядом с путём расположены доступные кнопки «Права на документы», «Загрузить» и «Новая папка».
В списке компаний видны типовые настройки ВЭД, разрешительных документов, контрактов и «По запросу».
В корне компании можно переопределить типовые настройки и настроить пользовательские папки первого уровня этой компании.
В таблице доступны роли и
исключения для сотрудников. Галочка в заголовке колонки меняет право у всех видимых строк на текущей странице.
У каждого сохранённого файла контекстное меню открывается правым щелчком по строке или кнопкой `⋯`, включая
списки документов в карточках и папки для просмотра. Для хранимых папок администратор выбирает
**«Права папки»** прямо в этом меню. Вложенные папки наследуют ограничения родительского пути.
В окне прав сохранённой папки недоступные из-за раздела или родительской папки действия отображаются без галочек.
При запрете просмотра рядом с ролью или сотрудником указано, откуда унаследован запрет. Массовое изменение
пропускает заблокированные действия.
Годы и месяцы наследуют правила ВЭД. Право «Переименование» проверяется отдельно для файлов и папок.
При переименовании сохраняются ID записи, прежний ключ MinIO и расширение файла.

Сервер проверяет правила при загрузке, скачивании и удалении. Разделы и папки без просмотра скрываются.
В карточках ВЭД с доступом к просмотру запрет загрузки отображается рядом с отключённой кнопкой. Для общих
документов рейса изменение должно быть разрешено в каждой связанной компании.

В новой поставке блок документов учитывает типовые права ВЭД и правила выбранной компании. При запрете
просмотра блок скрыт, при запрете загрузки файлы не принимаются даже во временный черновик. При сохранении
CRM повторно проверяет права по компании, записанной в поставке. Папки поставки наследуют права ВЭД и
ограничения своих родительских папок.

Перед использованием версии 2.0.73 примените миграции командой `yarn nocobase upgrade`. Предыдущая миграция переводит существующие
файлы и папки рейса в общий комплект, сохраняя их содержимое, вложенность и настройки доступа. Удаление связи с компанией
убирает рейс из её ветки каталога. Файлы остаются доступны в карточке рейса при наличии прав.
Файлы компании или рейса требуется удалить штатным способом перед удалением самой записи.

### Поиск файлов

Лупа справа в шапке, рядом с правами на документы, открывает поле поиска по части имени файла, в том числе по расширению. Поиск начинается с двух
символов. В корне он охватывает доступные компании, внутри папки — её содержимое и подпапки. Результаты заменяют
список в этом же окне и содержат кликабельный путь к папке. Имя открывает предпросмотр. Очистка поля возвращает к
содержимому текущей папки.

Сервер выбирает до 50 результатов за запрос, проверяя правила разделов, доступ к карточкам и права на вложенные
папки. Черновики в поиск не попадают. Миграция 2.0.97 создаёт два индекса PostgreSQL с `pg_trgm` по существующим
именам файлов в `process_documents` и `attachments`. Индексы обновляются автоматически при изменениях в CRM.
Объекты MinIO читаются при предпросмотре и скачивании.
